# Dependency-aware platform roadmap

All phases are proposed. No implementation starts in this task. Each phase begins by rechecking canonical main, open work, release/governance and source pins. No calendar commitment is justified by this research; phase exits are evidence-based. Preserve normal merge commits, exact-head qualification, identity, Alibaba OpenCodeReview and genuine TypeSafe Jev; never squash/rebase/force-push or qualify an old head.

## Ordering and ownership

Durability precedes production mutation. Tenant/authentication and deterministic sandbox precede live connectors. Read-only import/shadow proves value before switching money. One complete payment/settlement/refund path precedes connector breadth. Billing breadth follows durable existing-domain support; authority foundations are early, while full community/agent UX follows end-to-end money safety. Reconciliation, privacy and observability belong in every phase, not a cleanup phase at the end.

## Deployment and operational gates

Supported first stack: PostgreSQL plus one CoFi binary in API/worker roles and optional execution sidecar only if selected. Notifications/jobs/projections use PostgreSQL; Redis/Kafka/ClickHouse/Kubernetes are not prerequisites. Scale only when measured bottlenecks require them. Managed and self-hosted run the same economic rules/export format. Desktop does not become a second production financial database.

Before live money: restore and upgrade drills, authenticated scopes, secret/key handling, operator UNKNOWN procedure, provider account eligibility, legal role/liability review, PCI dataflow scope, reconciliation checks, monitoring ownership and incident freeze. These gates do not prevent bounded P0 storage implementation. They prevent unsafe production activation.

At each phase exit record exact base/head, commands/results, scope, changed invariants, imported units/dependency closure, risk, review results and remaining limitations. Publish only reproducible evidence. An OCR delegation preview is not a completed Alibaba review, and an agent's self-assessment is not genuine Jev evidence. A new commit invalidates prior head-qualified results; rerun affected required gates.

## Dependency changes from the founder's illustrative order

The test processor and authority foundation move before live connectors. Reconciliation/settlement and UNKNOWN recovery move into the first payment vertical rather than waiting for routing. Checkout is not a separate isolated phase: a usable, tokenized customer flow is part of the first complete payment product. Agent permissions arrive early; broad agent automation waits for shared budgets and qualified execution. Advanced regulated services remain provider-led and demand-driven.

## Release and ownership model

One named owner per grain/subsystem, one connector maintainer per qualified provider, an operational owner for unresolved attempts, and a rights/security owner for imported source closure. No contributor silently expands custody scope, enables a new rail or overwrites invariants. Existing dependency-bump PRs remain separate and are not absorbed into this plan. Early releases label sandbox/shadow/live qualifications precisely; the current release remains what its source/status documents actually establish.
