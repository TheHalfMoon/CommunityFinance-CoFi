## Priority model and copy modes

- **A:** targeted code/test implementation candidate with real near-term CoFi relevance. Verify its exact HEAD/SHA, file-level rights, ownership, transitives, compiled test and security before importing. Prefer small selected files or a versioned sidecar.
- **B:** useful provider SDK, test corpus, schema, or bounded subsystem; study and adapt after the core proves the preconditions. SDK and externally provided rails are not brandable independent capabilities.
- **C:** interesting but over-scoped, pre-alpha, poorly evidenced, or unrelated to the first money-flow wedge. Keep as a reference only.
- For every file import: preserve correct authorship/notices, record upstream+blob SHA+diff, test with kill/replay/tenant/currency/counterexample fixtures, and get permission/redistribution closure before publication. Account access to a copy of third-party code is **not** automatically ownership of its commercial rights.

## Critical source-level findings

**CoFi internal current code:** The current `cofi-storage/src/lib.rs` and `docs/implementation/G001_CODEC_COVERAGE.md` show many validated record codecs, not a completed all-registry durable PostgreSQL unit of work. The oct-2026 plan understated progress; the source itself states G001 remains partial. The user GitHub inventory reported 60 accessible repositories on the TheHalfMoon connection and two CoFi entries, including an archived earlier state.

**Payment and revenue:** Polar's `server/polar/models/webhook_delivery.py` has tenant and endpoint-specific delivery records; `server/polar/transaction/service/refund.py` ties refunds to processor and transaction accounting. These are code-backed reference paths, **not** an assertion that transplanting Polar's refund ledger will preserve CoFi's invariants. Square's official TypeScript SDK has `src/api/types/{Payment,Order,Refund}.ts` and exposes provider-specific source, amount, merchant location, and idempotency fields. CoFi should use SDK dependency/adapters, not copy Square's marks or imply provider capability.

**Banking:** `moov-io/achgateway/internal/incoming/odfi/returns.go` contains ACH return-event processing; `moov-io/fedwire20022` is the current target for direct Fedwire ISO 20022. Two older libraries are deprecated; do not accidentally port them. The `OpenBankProject/OBP-API/.../Connector.scala` file has an explicit AGPL header and many banking transports; using its design as reference is safer than pretending it supplies regulated bank access.

**Reconciliation:** `blnkfinance/blnk/reconciliation.go` actually implements reconciliation workflow with matches, unmatched records, data source, progress updates. The separate `reconifyhq/reconify` and `opensyndicate/reconcile` repositories provide read-only file matching candidates. Any fuzzy/LLM match is a *suggested case*, never an automatically posted financial fact.

**Security/webhooks:** `svix/svix-webhooks/server/svix-server/src/core/retry.rs` implements scheduled retries for an asynchronous function; allow this for idempotent **notification** delivery only. It must not be reused to blindly retry a payment with UNKNOWN provider acceptance. `moov-io/watchman/internal/search/service.go` includes indexed screening/search; sanctions matching is not itself regulatory approval.

**User GitHub sources beyond the existing October CoFi inventory:** `TheHalfMoon/Flind-archive` includes a detailed Checkout.com windowed payment sync (and DodoPayments import); `TheHalfMoon/Montral` has signed webhook verification and sandbox billing; `TheHalfMoon/Bostan` includes exact amount parsing/provenance fields and accounting schema; `TheHalfMoon/Skilit` has tenant-scoped idempotency; `TheHalfMoon/Ecra` has typed resource budgets; `TheHalfMoon/Gomrey` has opaque credential/cursor and tombstone semantics. These were **read**, not copied or run. The Flind source appears imported from PostHog and requires a separate origin/provenance check.

**Stablecoins:** `circlefin/cctp-go` includes transfer/attestation/resume code; pair with Circle-issued/partner APIs and multi-chain finality tests. Safe and OpenZeppelin help with audited wallet/token tooling but do not confer Circle issuer rights. Real transfers require operator/region and wallet custody compliance checks.

**Retail and commerce:** Saleor checkout source `saleor/checkout/payment_utils.py` models exact partial/overcharged statuses, useful for CoFi Commerce cases. Posnic and Safqah provide offline POS and Arabic RTL patterns; keep cash drawer/local inventory separate from shared canonical monetary truth and reconcile on sync. Do not treat a signed receipt as bank settlement.

## Required due diligence before any actual copying

- Confirm current upstream commit, ownership and repo redirected names. Inspect root license, each selected file's header, NOTICE, vendored trees, submodules, generated code, patent/trademark restrictions, and dependency graph.
- Confirm true gap versus CoFi `main` and any open work; do not shadow another active implementation. Prior CoFi `docs/research/SOURCE_EVIDENCE.json` already describes 31 older sources; the previous CoFi 2.0 plan adds 23 names, some also in this expanded code-level registry.
- Favor Rust-native code, separate Go adapters or direct official SDK dependencies; use a bounded RPC for incompatible runtimes. Never replace CoFi core's ledger and authority records with a donor's ledger.
- Security testing must include: wrong tenant scope, altered idempotency payload, concurrent double refund, commit-ack loss, webhook signature replay, stale sync cursor, delayed ACH return, payout grouping mismatch, chain reorg, double bridge attempts, unexpected rounding, revoked agent authority and restored pending work.
- No live bank, card, Circle issuer/USDC mint, ACH, or POS network capability is unlocked by source code alone; separate financial/partner/legal onboarding is necessary.
- Research alone does not satisfy build/reliability/independent review, and this plan does not turn P0 into a live-ready platform.
