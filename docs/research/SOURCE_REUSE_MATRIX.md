# Source reuse matrix

Research date 2026-10-07. This is a selection/qualification plan; **no donor source was imported, executed, benchmarked or security-qualified**. Full immutable revisions and root license receipts for every row are in [source evidence](SOURCE_EVIDENCE.md) and its machine-readable register. Repository names below identify those records; the pin, license and permission columns form part of each decision. Root licensing never substitutes for unit/dependency rights.

## Modes and permission

COPY = retain a licensed bounded source/fixture unit; PORT = reproduce selected behavior in CoFi types with attribution where derivative; ADAPT = retain useful structure with a changed ownership/interface boundary; EXTRACT CONTRACT = define the minimal independent interface; DEPENDENCY = consume a maintained package without owning its internals; SIDECAR = separately deployed bounded service; REFERENCE ONLY = use ideas/behavior as evidence, no source incorporation; REJECT = inappropriate/risky import; IRRELEVANT = outside the chosen product.

Apache/MIT reuse follows actual license, notice and dependency obligations. The founder explicitly granted reuse authorization only for `juspay/hyperswitch`, recorded as `FOUNDER-HYPERSWITCH-REUSE-2026-10-07`. Other founder projects do not inherit that permission by ownership/name. Missing-license units remain reference-only until an authorized rights basis is established. GPL/AGPL/LGPL boundaries require their own review; a process boundary does not automatically eliminate obligations. No private permission documents are included.

## Broader founder inventory and search limits

The accessible founder inventory was screened beyond names using code queries for idempotency, capability, connector, transaction and exact-head. Public inventory, selected pins, path/hash read receipts and coverage limits are in the evidence register. Additional indexed hits included MESC, Kodac, MedScale, Lilac and Tarif; they were screening references, not promoted to serious runtime donors without pinned implementation/rights/qualification. Graft was not accessible through the live repository lookup (404); its availability and semantics are unknown. No Graft dependency or fabricated gate is proposed. Private repository contents and metadata are not published here.

ERP/accounting systems are interoperability targets, not core replacements: export verified journal/receivable data with chart-of-accounts mappings and return evidence for reconciliation. Do not copy a full ERP, HR app, marketplace or fraud network. Treasury, KYC, tax, issuing, lending, identity and fraud capabilities use licensed provider contracts with eligibility evidence and fail-closed rules. Mature provider SDKs can be dependencies after package/license qualification; their service obligations cannot be copied as software.

## Qualification record for every future imported unit

Required fields: upstream repository/full revision/path/blob digest, destination/path/digest, license and notice location, permission reference, modification summary, owning subsystem/maintainer, resolved dependency closure/SBOM, deterministic and provider-sandbox tests, security review, PCI/data/credential scope, exact qualified CoFi head, divergence status, upstream vulnerability/patch monitor and removal/rollback procedure. Set state to planned -> rights_checked -> isolated -> conformance_tested -> security_reviewed -> exact_head_qualified. No field may be represented by a vague claim of production readiness.

Do not choose a donor because it has many files or a familiar language. Prefer a bounded implementation with a maintained dependency closure and reproducible failure behavior. Aggressive reuse should reduce verified engineering work; importing an unbounded runtime, a second financial truth or incompatible license makes CoFi larger and less trustworthy.
